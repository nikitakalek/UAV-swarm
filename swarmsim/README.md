# Пакет `swarmsim` — алгоритмы и симулятор SwarmCore

* **Модуль 1 (алгоритмы группы):** `alloc/`, `planning/partition.py`, `planning/routing.py`,
  `planning/validator.py`. Ими пользуются и симулятор, и бортовой узел
  [`swarmcore_node`](../docs/swarm_node.md).
* **Модуль 2 (симулятор и стенд):** `world.py`, `sim.py`, `agents/`, `missions/`,
  `scenario.py`, `eventlog.py` и др. — [docs/m2/README.md](../docs/m2/README.md).
* **Стыки:** `interfaces.py` (`Allocator.allocate(state, tasks) -> Assignment`,
  `MotionSource`, `CommsBus`, …). Модуль 1 работает прямо на них, без адаптеров.

## Модуль 1

| Файл | Что делает |
|---|---|
| [alloc/sector.py](alloc/sector.py) | `SectorAllocator` (в реестре — `sector`): секторы при старте, ремонт при событиях |
| [planning/partition.py](planning/partition.py) | деление области на компактные секторы равной площади (Вороной + Ллойд + power diagram) |
| [planning/routing.py](planning/routing.py) | порядок обхода задач аппаратом (ближайший сосед + 2-opt), оценка загрузки |
| [planning/validator.py](planning/validator.py) | `PlanValidator`: назначения, геозоны, граница, энергия, коридор высот, разнос |

### `SectorAllocator`

**Старт.** Рабочая область (объединение ячеек миссии) делится на N компактных секторов
равной площади (разброс площадей 1–2 %). Секторы сопоставляются аппаратам по минимуму
суммарного расстояния (перебор при N ≤ 7, иначе жадно). Задача достаётся сектору по
центроиду. Затем граничные ячейки перекладываются от самого загруженного аппарата к
соседу, пока это уменьшает время завершения миссии (makespan).

**Ремонт** (отказ, RTL, новая задача). Живые аппараты сохраняют план, текущая задача
не отбирается. Свободные задачи раздаются по одной: каждую берёт аппарат, который
закончит с ней раньше всех (текущая загрузка + путь от конца его маршрута). Затем то же
выравнивание по границе.

`SectorAllocator(repair=False)` — статический режим без перераспределения, для сравнения.

**Сравнение в симуляторе** (`stub_roundrobin` — заглушка М2, 5 зёрен):

| Сценарий | makespan, с: заглушка → sector | `T_recovery_max`, с |
|---|---|---|
| `sitl_small` (3 аппарата, отказ) | 161 → **149** | 70 → **58** |
| `failures` (10, два отказа + новая цель) | 572 → **491** | 263 → **191** |
| `nonconvex_nofly` | 650 → **565** | — |
| `random_failures` (20 % отказов) | 512 → **477** | 127 → 137 |
| `nominal`, 16 ячеек / 5 аппаратов | 798 → 863 | — |
| `nominal`, 64 ячейки / 5 аппаратов | 1393 → **988** | — |

На крупных ячейках (16 на 5 аппаратов) выигрыш съедает дискретность: секторы не могут
поделиться ровнее, чем по ячейке. Чем мельче ячейки, тем сильнее выигрыш.

Время расчёта начального плана: 36 задач / 3 аппарата — ~45 мс, 225 / 20 — ~170 мс
(`scripts/m1_pictures.py`).

### `PlanValidator`

Строит путь каждого аппарата так же, как его полетит `Agent` (обход бесполётных зон по
графу видимости, галсы с непройденной точки, возврат домой), и проверяет правила
`assignment`, `geozone`, `domain`, `energy`, `altitude`, `separation`. Нарушения не
исправляются, а возвращаются списком (`ValidationReport.describe()`).

На демо 5 аппаратов с одной площадки: все на 40 м — 9 нарушений разноса, эшелоны
через 4 м — 0 (`docs/img/plan_validation.png`).

## Запуск

```bash
./.venv/bin/swarmcore run --scenario scenarios/failures.yaml --seed 1 --set allocator.name=sector
./.venv/bin/python scripts/m1_pictures.py     # картинки в docs/img/ и время расчёта
./.venv/bin/python -m pytest -q tests/test_m1_alloc.py tests/test_m1_validator.py tests/test_partition.py
```
