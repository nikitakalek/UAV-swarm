# Техническое приложение

Сжатая техническая часть для экспертов и менторов. Полная исследовательская версия
(аудит концепции, требования, программа экспериментов, алгоритмы) — в [archive/](archive/).

## 1. Что взяли из прошлой версии (и почему это важно для продукта)

| Решение | Откуда | Зачем продукту |
|---|---|---|
| Функции безопасности исполняются **на борту**, а не на наземной станции | аудит, S5 | это и есть обоснование «модуля на плате»: при потере связи с землёй безопасность не пропадает |
| Аварийные режимы остаются за автопилотом | аудит, S14 | производитель не боится, что модуль «сломает» аппарат |
| **Валидатор плана**: геозоны, запас энергии (резерв 20 %), разнос аппаратов — до отправки на автопилот | требования SR-6 | недопустимый план не исполняется; сильный аргумент для производителя |
| Два слоя разведения: стратегическое (свои зоны + эшелоны по высоте) и тактическое уклонение (позже) | аудит, S5 | стратегического достаточно для MVP и агро; тактическое требует быстрого канала |
| Каждый узел хранит копию состояния миссии; децентрализованное распределение (CBBA — аукцион на основе консенсуса) при потере наземной станции | аудит, S6; алгоритмы | продолжение работы без оператора (v1) |
| Деление участка на **компактные** секторы равной площади (Вороной + выравнивание), а не полосы | код, `sectors.py` | меньше холостых перелётов |
| Не изобретать: VRP-солверы (OR-Tools), консенсус-протоколы, автопилот | алгоритмы | экономия времени маленькой команды |

Что **ушло** из фокуса: факторный эксперимент по 4 архитектурам, статистика,
модель обнаружения целей, «точка перехода» между центром и роем. Это хорошая
исследовательская тема (диплом, статья), но не нужна клиенту на этом этапе.

## 2. Архитектура ПО модуля

```
            swarm_node (один процесс на борт)
 ┌─────────────────────────────────────────────────────┐
 │  MissionState      — копия миссии: участки, задачи,  │
 │                      кто что делает, статусы         │
 │  Allocator         — деление участка, перераспределение│
 │  PlanValidator     — геозоны, энергия, разнос        │
 │  PeerLink          — обмен с соседями (UDP → mesh)    │
 │  VehicleLink       — MAVSDK → автопилот (MAVLink)     │
 │  Log               — журнал событий («чёрный ящик»)   │
 └─────────────────────────────────────────────────────┘
```

Интерфейс к аппарату (фиксируется в первую неделю MVP):
`arm()`, `takeoff(alt)`, `goto(lat, lon, alt)`, `land()`, `rtl()`, `get_state()` →
позиция, заряд, режим, исправность.

Ключевая идея: `VehicleLink` — единственное место, где код знает про PX4. Заглушка
вместо него позволяет тестировать логику без симулятора; позже так же добавится ArduPilot.

## 3. Что уже есть в коде (`swarmsim/`)

| Файл | Что делает | Статус |
|---|---|---|
| `sectors.py` | деление области: полосы, Вороной + Ллойд + power diagram | готово, тесты |
| `alloc.py` | распределители: статические, центральный аукцион с `reassign` после отказа, оракул | готово, тесты |
| `plan.py` | маршрут агента и валидатор плана | готово, тесты |

129 автотестов (`pytest`). Замер центрального аукциона: 625 задач распределяются за ~54 мс
при 5–50 аппаратах. Подробности — `swarmsim/README.md`.

## 4. Технический стек

| Слой | MVP | Позже |
|---|---|---|
| Автопилот | PX4 SITL | PX4 на реальном борту; ArduPilot |
| Связь с автопилотом | MAVSDK-Python, MAVLink/UDP | MAVLink/UART |
| Вычислитель | Raspberry Pi 4B | вычислительный модуль на своей плате-носителе |
| Связь «борт–борт» | Wi-Fi, UDP | mesh-радиомодуль |
| Язык | Python (+ NumPy, Shapely) | C++ для критичных по времени частей — по профилированию |
| Наземное ПО | CLI + QGroundControl для карты | плагин/своё приложение |

## 5. Технические ограничения, о которых знаем

- MAVLink в режиме внешнего управления (offboard) работает на частотах порядка 10–50 Гц —
  этого мало для тактического уклонения через канал; поэтому разведение в MVP — стратегическое.
- MAVLink по умолчанию не шифруется и не аутентифицируется — для серии нужен защищённый канал.
- Синхронизация времени между бортами (GPS/NTP) нужна для корректного лога и перераспределения.
