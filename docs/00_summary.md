# SwarmCore — резюме проекта

> Рабочее название. Новое название обсуждается (см. раздел «Открытые вопросы»).
> Документ — основа для заявки в акселератор МАИ (подача до 20 ноября 2026).

## Одной фразой

**Плата с ПО, которая подключается к полётному контроллеру серийного беспилотника и
позволяет одному оператору вести группу аппаратов как один: распределять работу между
ними, разводить их в воздухе и продолжать миссию, если один аппарат выбыл.**

## Проблема

В гражданском применении БВС (беспилотных воздушных судов) — агрообработка, аэрофотосъёмка,
мониторинг — сегодня действует правило «один аппарат — один оператор». Узкое место — не
дроны, а люди: квалифицированных операторов мало, а выработка экипажа ограничена одним
аппаратом.

- Китайские производители эту проблему уже решили на своей стороне: например, DJI ещё
  с агродроном MG-1P позволял одним пультом управлять **до 5 аппаратов** одновременно.
- После ухода китайских поставщиков с российского рынка отечественные производители
  выпускают аппараты на открытых автопилотах (PX4/ArduPilot), где **групповой работы
  «из коробки» нет**. Каждому производителю пришлось бы разрабатывать её самому.

## Решение

Бортовой модуль SwarmCore = **компаньон-компьютер + радиомодуль для связи «борт–борт» +
наше ПО**. Ставится на каждый аппарат группы, подключается к полётному контроллеру по
MAVLink (стандартный протокол обмена с автопилотом), сам автопилот не меняется.

Что получает оператор:
1. Ставит одну задачу на группу («обработать поле», «отснять участок»), а не на каждый
   аппарат.
2. Модули сами делят работу между аппаратами с учётом заряда и положения.
3. Аппараты разведены по высотам и зонам — не мешают друг другу.
4. Если аппарат ушёл на заправку/замену батареи или отказал — его участок забирают другие.
5. Безопасность исполняется на борту: потеря связи с наземной станцией не роняет миссию.

## Клиент

**Покупатель — производитель БВС** (B2B): встраивает модуль в свою линейку и продаёт
аппараты с функцией группового применения. **Конечный пользователь** — компании-эксплуатанты
(агросервисы, геодезия, мониторинг инфраструктуры).

Первый сегмент для проверки (гипотеза): **производители агродронов**. Там понятна
экономика (оплата за гектар, сезонность, дефицит операторов) и задача хорошо делится
между аппаратами.

Применение — **строго гражданское**.

## Почему мы

- Профильное образование: МАИ, «Системы управления летательными аппаратами».
- Уже есть работающее ядро алгоритмов: разбиение области между аппаратами, распределение
  и перераспределение задач, валидатор плана, бортовой узел с обработкой отказов
  (Python, 170 автотестов).
- Стек совместим с тем, на чём строят отечественные аппараты: PX4, MAVLink, Raspberry Pi.

## Что будет к подаче заявки (20 ноября)

Демонстрация «модуля на плате»: Raspberry Pi 4B с нашим ПО управляет группой из 2–3
виртуальных аппаратов в симуляторе PX4 (SITL — программная модель автопилота, тот же код,
что летает на реальной плате). Сценарий: оператор ставит одну задачу → аппараты делят
участок → один «отказывает» → остальные доделывают его часть. Видео + лог.

Параллельно — первые интервью с производителями и эксплуатантами (сейчас контактов нет).

## Бизнес-модель (гипотеза)

Плата (железо) продаётся производителю за единицу + лицензия на ПО (разово за борт или
подписка на обновления) + платная интеграция под конкретный аппарат. Цены — после
интервью с клиентами, подробности в [04_business_model.md](04_business_model.md).

## Команда

2 человека — достаточно для MVP. Расширение команды (встраиваемые системы/радио, продажи)
— после подтверждения спроса. См. [07_team.md](07_team.md).

## Чего просим у акселератора

1. Выход на производителей БВС и эксплуатантов (интервью, пилот).
2. Менторы по B2B-продажам в промышленность и по регуляторике полётов.
3. Доступ к реальным аппаратам/полигону для первого лётного теста.
4. Подготовка к грантам (ФСИ «Студенческий стартап» и аналогичные).
