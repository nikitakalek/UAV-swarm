# Наземная станция SwarmCore (пульт оператора и 3D-вид)

Два экрана в браузере, всё на одной машине:

* **Пульт** (`http://127.0.0.1:8080/`) — карта OpenStreetMap/спутник, разметка, план,
  запуск, телеметрия, команды и изменение миссии в полёте.
* **3D-вид** (`/view`) — живая сцена Three.js поверх той же подложки: секторы, эшелоны,
  следы, отказы, передача задач. Открывается кнопкой «3D-вид ↗» в отдельном окне — его
  можно перетащить на второй монитор.

```bash
./.venv/bin/python -m swarmcore_gcs          # откроет пульт в браузере; Ctrl+C — выход
```

Сервер запускает узлы `swarmcore_node` (по процессу на аппарат) и говорит с ними по UDP,
как настоящая станция. Сейчас аппараты — кинематическая модель с ускорением 1–10×;
переход на PX4 SITL — те же узлы с `--vehicle mavsdk` (пульт не меняется).

## Сценарий оператора

1. **Разметка.** «Нарисовать участок» — щелчки по углам, замкнуть на первой точке.
   «Добавить зону» — бесполётная зона (правый щелчок по зоне — удалить). «Ставить
   площадки» — щелчок по карте ставит площадку аппарата (число площадок = число
   аппаратов, перетаскиваются, правый щелчок — удалить). «Пример» — готовое поле.
2. **Параметры.** Высота первого эшелона и шаг (≥ 3 м), скорость, ширина полосы (шаг
   галсов), размер ячейки, ёмкость батареи, ускорение симуляции.
3. **Проверить план.** Сервер считает то же, что лидер на борту: секторы, маршруты, время,
   энергию и замечания валидатора. На карте — ячейки в цвет аппарата и маршруты.
   «Запуск миссии» доступен, только если валидатор не нашёл нарушений.
4. **Полёт.** Аппараты и их следы на карте, ход миссии, таблица бортов (режим, высота,
   заряд, текущая ячейка, ★ — лидер), лента событий.
   * Команды группе: «Пауза»/«Продолжить», «Все домой», «Остановить миссию».
   * Каждому борту: ⌂ — домой, ⚡ — имитация разряда, ✕ — имитация отказа (процесс узла
     убивается, как при потере борта).
   * «Отключить связь пульта» — пульт замолкает; группа переходит в `NO_GCS` и продолжает.
   * **Изменить миссию в полёте:** «Новая бесполётная зона» или «Добавить участок» —
     нарисовать контур; группа примет ревизию и перестроит план, не садясь.
5. **Конец.** «Повтор в 3D ↗» — повтор миссии со шкалой времени (`/replay`), журналы — в
   `runs/gcs/<дата-время>/`.

## Устройство

| Модуль | Что делает |
|---|---|
| `swarmcore_gcs/geo.py` | широта/долгота ↔ локальные метры от первой площадки |
| `swarmcore_gcs/mission.py` | черновик с карты → сценарий; предпросмотр плана; проверка изменений в полёте |
| `swarmcore_gcs/session.py` | запуск узлов, цикл станции (`GroundStation`), лента событий, снимок состояния |
| `swarmcore_gcs/server.py` | HTTP: страницы, API, поток телеметрии (SSE, 4 раза в секунду), тайлы |
| `swarmcore_gcs/tiles.py` | тайлы OSM и Esri World Imagery через кэш `~/.cache/swarmcore/tiles` |
| `swarmcore_gcs/static/` | `gcs.html` (Leaflet + Geoman), `view3d.html` (Three.js) |

API — в шапке `swarmcore_gcs/server.py`.

## Ограничения

* Одна миссия за раз; сервер и узлы на одной машине (узлы на Raspberry Pi — #53).
* Тайлы берутся из интернета при первом просмотре места, дальше — из кэша. Правила
  OpenStreetMap не разрешают массовую выгрузку: для демо и разработки этого достаточно,
  для продукта нужен свой сервер тайлов или коммерческий поставщик.
* Если аппарат оказался внутри только что нарисованной зоны, лидер несколько секунд
  отклоняет планы (это видно в ленте), пока аппарат не выйдет из зоны.
* Пульт открыт только на этом компьютере. `--host 0.0.0.0` открывает его в локальной
  сети — без пароля, только для стенда.
