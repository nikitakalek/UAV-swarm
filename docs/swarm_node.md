# Бортовой узел `swarm_node` (модуль 1)

Один процесс на аппарат. Узел видит только **свой** аппарат (через `MotionSource`) и
**соседей** (через канал `PeerLink`). Общей «головы» нет: состояние миссии есть копией
на каждом борту, распределение считает лидер, а при его выбытии роль сразу берёт
следующий.

```
            swarmcore_node.SwarmNode (один процесс на борт)
 ┌──────────────────────────────────────────────────────────────┐
 │ состояние миссии  — сценарий, задачи, план, кто что сделал    │
 │ SectorAllocator   — секторы при старте, ремонт при отказе     │  swarmsim/alloc/sector.py
 │ PlanValidator     — назначения, геозоны, энергия, высоты      │  swarmsim/planning/validator.py
 │ ModeMachine       — NORMAL / NO_GCS / DEGRADED / RTL / DONE   │  swarmcore_node/modes.py
 │ PeerLink          — UDP сейчас, mesh-радио потом              │  swarmcore_node/link.py
 │ MotionSource      — KinematicMotion или MavsdkMotion (PX4)    │  swarmsim/agents, swarmcore_px4
 │ EventLog + трасса — журнал решений с причинами                │
 └──────────────────────────────────────────────────────────────┘
```

## Как работает

1. **Одна команда группе.** Наземная станция рассылает миссию (сценарий YAML: область,
   бесполётные зоны, состав, высоты). Каждый узел сам строит из неё одинаковый набор
   задач (ячейки поля + «змейка» внутри ячейки).
2. **Лидер** — узел с минимальным id среди живых. Когда все соседи прислали позиции, он
   делит рабочую область на компактные секторы равной площади, отдаёт каждый ближайшему
   аппарату, выравнивает загрузку по граничным ячейкам и строит порядок обхода.
3. **Валидатор** проверяет план так, как его полетят аппараты (с обходом бесполётных
   зон): каждая задача ровно у одного, нет пересечения зон и выхода за границу, хватает
   батареи с резервом 20 %, высоты в коридоре, аппараты на одной высоте не сближаются.
   **Недопустимый план не публикуется и не исполняется**; лидер в режиме `DEGRADED`,
   причина видна оператору.
4. **Разведение:** каждый аппарат на своём эшелоне (`altitude + id · altitude_step`,
   ≥ 3 м) и в своём секторе. Обход зон — по графу видимости при исполнении.
5. **Heartbeat** каждые 0,5 с: позиция, режим, текущая задача и её прогресс, все
   известные выполненные задачи, расход энергии, версия плана. «Выполнено» и «прогресс»
   только растут, поэтому потери и повторы сообщений не ломают копии состояния.
6. **Отказ соседа** — тишина дольше 2,5 с. Лидер пересчитывает план: живые сохраняют
   свои задачи, задачи выбывшего отдаются по одной тому, кто с ней закончит раньше всех,
   и продолжаются **с непройденной точки галса**. Новый план — с большей версией;
   побеждает план с наибольшей версией (при равенстве — от меньшего id).
7. **Отказ лидера** — то же самое: следующий по id узел уже имеет копию состояния и
   становится лидером.
8. **Нет наземной станции** — режим `NO_GCS`, миссия продолжается.
9. **Низкий заряд** (остаток минус путь домой ниже резерва) или команда оператора —
   `RTL`: аппарат возвращается, его задачи забирают остальные.
10. Сделал своё — возвращается и садится; миссия завершена — `DONE`.

Аварийные режимы автопилота (failsafe PX4) узел не отключает: если процесс узла умер,
PX4 сам выполнит действие по потере offboard-управления.

## Режимы (`ModeMachine`)

Приоритет: `DONE > RTL > DEGRADED > NO_GCS > NORMAL > IDLE`.

| Режим | Когда | Что делает узел |
|---|---|---|
| `IDLE` | нет миссии | ждёт |
| `NORMAL` | связь с группой и станцией есть | исполняет план |
| `NO_GCS` | нет heartbeat станции > 5 с | исполняет план, решения на борту |
| `DEGRADED` | потерян сосед, а план ещё не пересчитан; или план отклонён валидатором | исполняет прежний план, лидер пересчитывает |
| `RTL` | команда оператора, низкий заряд | летит домой, задачи отдаёт |
| `DONE` | на земле, миссия завершена (или после RTL) | шлёт heartbeat и выключается |

## Сообщения

JSON в одной UDP-датаграмме, поле `v` — версия протокола (`swarmcore_node/messages.py`).

| kind | от кого | содержимое |
|---|---|---|
| `mission` | станция | сценарий, `mission_id`; повторяется, пока все узлы не подтвердят |
| `gcs_hb` | станция | признак жизни, команда (`rtl`, `fail:<id>` — имитация отказа) |
| `hb` | узел | см. п. 5 выше |
| `plan` | лидер | версия, состав, выбывшие, план каждого аппарата, причины назначений |

## Журнал

У каждого узла `node_<id>_events.jsonl` (формат `docs/m2/eventlog_format.md`) и
`node_<id>_trace.csv`. Каждое переназначение (`assign`) хранит причину и ссылку на
событие, которое его вызвало: `peer_lost → plan_published → assign`. Станция пишет все
heartbeat (`gcs_heartbeats.jsonl`) — из них строится картинка и проверки.

## Запуск

Всё на одной машине (кинематическая модель, ускорение ×10, отказ аппарата 1 на 40-й с):

```bash
./.venv/bin/python -m swarmcore_node demo --fail 1@40 --time-scale 10 --out runs/demo
```

В `runs/demo/`: журналы, `summary.json` с проверками критериев MVP, `demo.png`.

По отдельности (так же — на Raspberry Pi, каждый узел своим процессом):

```bash
./.venv/bin/python -m swarmcore_node node --id 0 --n 3 --home 0,0
./.venv/bin/python -m swarmcore_node node --id 1 --n 3 --home 4,0
./.venv/bin/python -m swarmcore_node node --id 2 --n 3 --home 8,0
./.venv/bin/python -m swarmcore_node gcs --mission scenarios/demo_field.yaml --fail 1@40
```

С PX4 SITL (стенд участника Б): поднять симуляторы
`HOMES="0,0 4,0 8,0" swarmcore_px4/sitl/multi_sitl.sh 3`, затем узлы с `--vehicle mavsdk`
и `--time-scale 1` (адрес аппарата по умолчанию `udpin://0.0.0.0:14540+id`). Если узлы на
Pi, а SITL на Mac — `--vehicle-address udpin://0.0.0.0:<порт>` и маршрутизация MAVLink с
Mac на Pi; адреса соседей — `--peers host:port,...`, станции — `--gcs host:port`.
Этот режим ещё **не проверен** на SITL — это следующий шаг стенда.

## Проверено (тесты)

* `tests/test_swarm_node.py` — 21 тест на группе узлов в памяти: штатная миссия, отказ
  ведомого и лидера (новый план ≤ 5 с), продолжение с прогресса, 30 % потерь сообщений,
  без станции, RTL по команде и по заряду, отклонённый план (никто не взлетает),
  10 аппаратов с двумя отказами, эшелоны, причины переназначений.
* `tests/test_swarm_node_udp.py` — те же процессы по UDP с отказом (убийство процесса).

## Честные ограничения

* Распределяет лидер; при разрыве сети на две части каждая выберет своего лидера и
  может продублировать задачи. После восстановления связи версии планов сходятся,
  выполненное не повторяется, но работа во время разрыва может удвоиться. Полностью
  децентрализованное распределение (CBBA) — v1.
* Разведение стратегическое (эшелоны + секторы), тактического уклонения нет.
* Энергия — оценка `P · длина / v` с постоянной мощностью; реальную модель и заряд
  с автопилота подключим на стенде.
* Сообщения не шифруются и не подписываются.
